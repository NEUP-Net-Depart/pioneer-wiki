Pioneer Wiki - deployment notes
----------------------------------------------------------------------
Image:  pioneer-wiki:latest, also tagged pioneer-wiki:<tag> for rollback
Files:  pioneer-wiki-linux-amd64.tar.gz   the image (docker save format)
        docker-compose.yml                the run file
        DEPLOY.txt                        this file
        default.env.example               template the script copies to .env

The easy path is the deploy script on the host. Run it from the directory you
want the install in (or pass --dir PATH); it fetches these four files into that
directory, loads the image and starts the service:

    curl -fsSL -o deploy.sh https://raw.githubusercontent.com/NEUP-Net-Depart/pioneer-wiki/main/deploy/deploy.sh
    bash deploy.sh

Running that again installs the newest release; pass a tag to pin one. On the
first run it saves default.env.example locally as .env.example, writes .env and
stops there, so the two Supabase values can be filled in; running it again picks
up where it left off. An existing .env is never overwritten.
The image archive stays in the directory under the name below, which is the file
step 2 loads.

Doing it by hand instead:

1. Check that the host matches this image (built for x86_64):

       uname -m        # expect x86_64

2. Load the image:

       gunzip -c pioneer-wiki-linux-amd64.tar.gz | docker load

3. Put docker-compose.yml next to a .env holding the two public Supabase
   values — copy the release's default.env.example and edit it:

       cp default.env.example .env
       # .env
       NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
       NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key

   The service starts with PIONEER_DATA_SOURCE=supabase, so a missing or
   misspelled value fails loudly instead of serving mock fixtures.

4. Start it (it listens on 127.0.0.1:3000 only):

       docker compose up -d

5. Point DNS for domain(eg. wiki.example.com) at the server (A/AAAA for its IP, or CNAME
   for an existing hostname), then point the existing Caddy at it. The root
   CNAME file records the domain; it does not configure DNS or the proxy:

       wiki.example.com {
           encode zstd gzip
           reverse_proxy 127.0.0.1:3000
   }

Before the first deployment the Supabase project needs the schema from
supabase/migrations (in the release's source archive), applied in filename
order, with the site URL and URL/auth/callback allowed as a redirect
targets. Content is imported once from a checkout with pnpm run seed-supabase.
